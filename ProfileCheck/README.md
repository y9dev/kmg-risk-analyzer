# Identity Risk Analyzer

Backend MVP для проекта Infrastructure Risk Radar. Главный источник — тестовый Microsoft Active Directory: сервер сам читает его по LDAPS, считает риски и отдаёт готовую статистику и находки дэшборду. Браузер не передаёт список пользователей для анализа. Демо режим запускается без домена и дополнительных библиотек. Партнёрский Certificate Radar подключается к будущему общему дэшборду через отдельный модуль.

## Быстрый запуск

Python 3.10 или новее. Для демо установка пакетов не нужна.

```bash
cd identity_risk_analyzer
python run.py
```

В PowerShell: `python run.py`. Сервис слушает только `127.0.0.1:8000`; порт можно сменить через `RADAR_PORT`. API-ключ для локального MVP не требуется. Не публикуй этот API через прокси или туннель без аутентификации на стороне сервера: отчёты содержат информацию об учётных записях и правах.

Открой `http://127.0.0.1:8000/` в браузере. По умолчанию выбрана Active Directory; кнопка запуска заставляет сервер прочитать AD DS и вычислить отчёт. Пока стенд не готов, выбери «Демо данные». Результаты и CSV появятся после сканирования.

```bash
curl -X POST http://127.0.0.1:8000/api/v1/scans -H 'Content-Type: application/json' -d '{"source":"demo"}'
curl http://127.0.0.1:8000/api/v1/summary
curl 'http://127.0.0.1:8000/api/v1/findings?severity=High'
curl -o identity-risks.csv http://127.0.0.1:8000/api/v1/export.csv
```

### Тестовый Active Directory

```bash
pip install -r requirements.txt
export RADAR_LDAP_HOST="dc01.demo.local"
export RADAR_LDAP_BASE_DN="DC=demo,DC=local"
export RADAR_LDAP_BIND_DN="CN=radar-reader,OU=Service Accounts,DC=demo,DC=local"
export RADAR_LDAP_BIND_PASSWORD="<secret>"
export RADAR_LDAP_CA_FILE="/path/to/ca.pem"
curl -X POST http://127.0.0.1:8000/api/v1/scans -H 'Content-Type: application/json' -d '{"source":"ldap"}'
```

Нужны только права читать выбранные объекты AD и свойства домена, **Domain Admin не нужен**. Подключение только LDAPS 636 с обязательной проверкой сертификата. Не добавляй пароль в URL, конфиг или демонстрационный JSON. Для эксплуатации секреты передаются окружением процесса через секретное хранилище и регулярно ротируются. Учётная запись bind не изменяет AD; сканер выполняет только LDAP search и unbind.

Для проверки на настоящем стенде используй DNS-имя контроллера, указанное в его TLS-сертификате, и доверенный корневой сертификат в PEM. Проверь `Test-NetConnection dc01.demo.local -Port 636`, затем запусти анализ с источником «Тестовый AD (LDAPS)». Новые аккаунты без входов ещё не считаются неактивными: при стандартном пороге 90 дней для этого нужны учётные записи, созданные более 90 дней назад, либо старые данные `lastLogonTimestamp`. Не подменяй этот атрибут ради демо; для мгновенного показа всех сценариев используй демонстрационные данные.

## Контракт API

| Метод и путь | Назначение |
| --- | --- |
| `GET /` | Локальная страница с результатами анализа |
| `GET /health` | Локальная проверка процесса без данных AD |
| `POST /api/v1/scans` | Запускает чтение AD DS сервером; `{}` по умолчанию. Для проверки без стенда — `{ "source": "demo" }` |
| `GET /api/v1/summary` | Сводный балл, количество находок и охват |
| `GET /api/v1/findings?severity=High` | Находки, причины, доказательства, действия |
| `GET /api/v1/report` | Полный отчёт, включая учётные записи |
| `GET /api/v1/history` | История запусков за время жизни процесса |
| `GET /api/v1/export.csv` | CSV в UTF-8 с BOM; безопасный вывод в Excel |
| `GET /api/v1/config` | Пороговые значения |
| `POST /api/v1/config` | `{ "thresholds": { "inactive_days": 120 } }` |

API доступен без ключа только с того же компьютера через loopback. Доступ к localhost могут иметь другие локальные процессы и пользователи; не запускай сервис на общей машине без дополнительных ограничений. API сознательно не принимает путь к произвольному файлу или произвольный LDAP-сервер: источник задаёт администратор окружением. Отчёты и история находятся только в памяти и очищаются после перезапуска. Журнал действий `audit.log` содержит тип действия и число объектов, но не пароли или содержимое запросов. Ограничь права на журнал и доступ к процессу. `RADAR_AUDIT_FILE` меняет его путь.

## Смысл оценок

Каждая находка получает балл от базовой тяжести правила и +10 при наличии административных прав (кроме правил, где это уже заложено); максимум 100. Риск учётной записи — сумма баллов её находок с ограничением 100. `security_score = 100 - средний риск учётных записей`. В `counts` считаются **находки**, а не уникальные учётные записи. Пороги уровней по умолчанию: Low 1, Medium 25, High 50, Critical 75. Пустой каталог даёт `security_score: null`.

Сервисный статус по LDAP определяется наличием SPN либо размещением в OU `Service Accounts`; на конкретном стенде эту эвристику нужно адаптировать. Проверка разрешённого интерактивного входа срабатывает только при отдельной подтверждённой оценке политики входа: по атрибуту AD делать вывод нельзя. Если атрибут владельца неизвестен, находка `SERVICE_NO_OWNER` не создаётся. `lastLogonTimestamp` реплицируется с задержкой, поэтому даты приблизительны. Упрощённые сигналы brute force/spray требуют импортированных событий 4625 с временем, источником и именем аккаунта; текущий LDAP адаптер их не собирает. Доменная политика не включает Fine Grained Password Policies. Для стандартных административных групп используются известные SID; для других групп проверка по имени зависит от локализации домена. В формате снимка можно передать `critical_groups` или пометить группу `critical: true`.

## Расширение

`radar/sources.py` нормализует источник в единый inventory; `radar/core.py` обрабатывает правила без доступа к сети; `radar/api.py` предоставляет контракт дэшборду. Следующий источник добавляется отдельной функцией, правило — в `RULES` и `analyze`. При подключении Certificate Radar общий дэшборд обращается к двум API и отображает отдельные разделы. Для продакшена нужны дополнительные меры: защищённая аутентификация, сохранение истории, постраничная выдача, ограничение частоты запусков и проверка прав на реальном стенде.
